pa-fhir-poc

A reference pipeline for a general problem: turning authoritative prose documents into validated, machine-readable artifacts without ever trusting an LLM unsupervised. A local model extracts requirements from the source PDF, a Neo4j graph holds them as reviewable facts, and a durable Temporal workflow blocks until a named human approves — only then are artifacts projected, and every claim of correctness is backed by an official validator rather than asserted.

The domain instance is healthcare prior authorization: Medicare coverage policies in, Da Vinci CRD/DTR FHIR artifacts out, validated with zero errors. The CMS Interoperability and Prior Authorization Final Rule (CMS-0057-F) gives the pattern a deadline — impacted payers must stand up prior-authorization APIs by January 1, 2027, and each faces this same first step: digitizing prose policy into FHIR, with governance.

TypeScript · Neo4j · Temporal · Ollama · MIT license

fhir-zod-gen

The complementary half of the validation story: a code generator that turns FHIR Implementation Guide profiles into Zod schemas — a runtime validator and an inferred TypeScript type in one plain, readable declaration. FHIR's mature validation tooling lives in Java; an ever-growing share of health-tech code (SMART on FHIR apps, Node backends, AI agents) lives in TypeScript, with no equivalent. It consumes the FHIR Schema intermediate format rather than raw StructureDefinitions, aiming to be the TypeScript sibling of Health Samurai's Python/Pydantic generator.

Where pa-fhir-poc uses the official HL7 validator as the offline oracle, generated Zod schemas are the in-process guardrail — profile conformance checked on every projection, no Java or Docker in the loop. v0.1 covers cardinality, nested elements, required bindings, and choice types; the roadmap starts at automatic IG-package resolution.
